2. Descripción de la aplicación

Clínica Salud es una aplicación web para gestionar los pacientes de una clínica y las citas asociadas a cada uno. La aplicación permite realizar las operaciones básicas de mantenimiento (CRUD) sobre dos entidades relacionadas:

  • Pacientes: listado, alta, edición y borrado.
  • Citas: listado, alta, edición y borrado.

La relación entre ambas entidades es 1:N: un paciente puede tener muchas citas y cada cita pertenece a un único paciente. Al borrar un paciente se eliminan también sus citas gracias a la configuración en cascada de Hibernate.

La interfaz está formada por una página de inicio con accesos directos, un listado de pacientes, un listado de citas y un formulario para cada entidad. Todos los formularios validan los datos antes de guardarlos y muestran mensajes de error junto a los campos incorrectos.

6. Base de datos

El esquema se crea con schema.sql y los datos de prueba se cargan con data.sql. La configuración está en application.properties: 

spring.datasource.url=jdbc:h2:mem:clinica;DB_CLOSE_DELAY=-1
spring.jpa.hibernate.ddl-auto=none
spring.sql.init.mode=always
spring.sql.init.encoding=UTF-8
spring.h2.console.enabled=true
server.port=8080

schema.sql

DROP TABLE IF EXISTS cita;
DROP TABLE IF EXISTS paciente;

CREATE TABLE paciente (
    id       BIGINT AUTO_INCREMENT PRIMARY KEY,
    nombre   VARCHAR(100) NOT NULL,
    email    VARCHAR(120) NOT NULL,
    telefono VARCHAR(30)
);

CREATE TABLE cita (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    fecha       DATE         NOT NULL,
    motivo      VARCHAR(200) NOT NULL,
    paciente_id BIGINT       NOT NULL,
    CONSTRAINT fk_cita_paciente
        FOREIGN KEY (paciente_id) REFERENCES paciente (id)
);

7. Arquitectura Controller · Service · Repository

La aplicación sigue una arquitectura por capas:

  • Controller: recibe las peticiones HTTP, valida a través del servicio y elige la vista.
  • Service: contiene la lógica de negocio y las reglas de validación.
  • Repository: acceso a datos mediante Spring Data JPA e Hibernate.
  • Model: entidades JPA que representan las tablas.
  • View: plantillas Thymeleaf que muestran los datos y formularios.

Rutas principales

MétodoRutaAcción
GET/Página de inicio con contadores.
GET/pacientesListado de pacientes.
GET/pacientes/nuevoFormulario de alta de paciente.

Ejemplo de entidad: relación 1:N

@Entity
@Table(name = "paciente")
public class Paciente {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String nombre;
    private String email;
    private String telefono;

    @OneToMany(mappedBy = "paciente", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Cita> citas = new ArrayList<>();
}

@Entity
@Table(name = "cita")
public class Cita {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private LocalDate fecha;
    private String motivo;

    @ManyToOne(fetch = FetchType.EAGER, optional = false)
    @JoinColumn(name = "paciente_id", nullable = false)
    private Paciente paciente;
}

8. Validación de formularios y gestión de errores

La validación se realiza en la capa de servicio y devuelve un mapa de errores por campo:

CampoRegla de validación
Paciente · nombreObligatorio, entre 2 y 100 caracteres.
Paciente · emailObligatorio, formato válido y no repetido.
Paciente · teléfonoOpcional; solo números, espacios, + y -.
Cita · fechaObligatoria y con formato de fecha válido.
Cita · motivoObligatorio, entre 3 y 200 caracteres.
Cita · pacienteDebe seleccionarse un paciente existente.

Cuando hay errores, el formulario se vuelve a mostrar con los datos introducidos y un mensaje junto a cada campo incorrecto. Para los errores de recurso no encontrado (por ejemplo, editar una cita que ya no existe) se muestra una página 404 controlada, y para cualquier fallo inesperado una página 500. La gestión centralizada se realiza con @ControllerAdvice y @ExceptionHandler.

10. Pasos de despliegue en otro entorno

  1. Instalar Java 17 (JRE o JDK) en el equipo de destino.
  2. Copiar el fichero app.jar generado en target/.
  3. Abrir una terminal en la carpeta donde esté el JAR.
  4. Ejecutar: 
    java -jar app.jar
  5. Abrir el navegador en http://localhost:8080.
  6. Para detener la aplicación, pulsar Ctrl + C en la terminal.

No es necesario instalar Maven ni copiar el código fuente: el JAR contiene la aplicación y todas sus dependencias. La base de datos H2 se crea en memoria al arrancar y se carga con los datos de data.sql.

Empaquetado desde el código fuente

empaquetar.bat        (equivale a: mvn package -DskipTests)

El resultado es target/app.jar, listo para ejecutar en cualquier equipo con Java 17.

13. Conclusión

El proyecto implementa una aplicación web completa con Spring MVC e Hibernate, siguiendo una arquitectura por capas y aplicando validación de formularios, gestión centralizada de errores y pruebas automáticas. La relación 1:N entre pacientes y citas permite comprobar el funcionamiento del mapeo objeto-relacional y de las operaciones CRUD sobre ambas entidades.

El uso de Maven y Git facilita la construcción reproducible del proyecto y el seguimiento de los cambios. El empaquetado en un único app.jar permite desplegar la aplicación en cualquier equipo con Java 17 de forma sencilla.
